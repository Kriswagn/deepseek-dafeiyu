# 大肥鱼记忆管理与可视化调研

核查日期：2026-10-29。以下结论来自项目仓库及官方文档；未安装第三方服务，未向这些项目上传聊天或密钥。

## 当前部署

现有机器人是 SAKURAfan1023/dafeiyu-bot 的 Swift 版本，运行于专用 Ubuntu。它不使用 AstrBot 插件系统。现有记忆按好友和群隔离，保存提炼的重点和摘要，采用本地关键词检索；当前每次长期记忆注入预算为 1800 字符。

因此，AstrBot 的插件不能直接放进本项目目录就生效。采用它们需要迁移聊天框架，或另外开发与现有程序之间的适配接口。研究可视化效果与替换实际记忆后端应分别决策。

## 最贴近需求的项目

### 1. LivingMemory（灵犀）

- 仓库：https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory
- 管理界面说明：https://lxfight-s-astrbot-plugins.github.io/astrbot_plugin_livingmemory/webui
- 仓库说明的能力：自动提炼；关键词、向量及图谱融合召回；会话/人格隔离；归档、衰减与访问强化；记忆编辑、导入导出和召回调试；2D/3D 图谱。
- 它是实际记忆管理插件，图谱为其管理界面的一部分。官方文档要求 AstrBot 的插件视图环境，并配置总结模型及 Embedding 提供方。
- 对本项目的判断：在“可管理的长期记忆 + 星系图谱”这个目标上最值得优先评估；接入成本主要是框架适配，而不是画星图。

### 2. Mnemosyne

- 仓库：https://github.com/lxfight/astrbot_plugin_mnemosyne
- 能力：自动总结、向量检索、会话隔离、记忆编辑、实时 Canvas 拓扑。默认 Chroma，可配置其他向量存储。
- 依赖 AstrBot 的模型及 Embedding Provider。
- 对本项目的判断：适合研究较直接的“总结 + 检索 + 管理面板”路线，但同样需要适配，不能直接装入 Swift 版本。

### 3. 大肥鱼 · 记忆星海

- 仓库：https://github.com/whyever77/dafeiyu-astrbot
- 展示模块：https://github.com/whyever77/dafeiyu-astrbot/tree/main/deploy/memory_observatory
- 它与当前部署是同名但不同实现的大肥鱼项目，基于 AstrBot。
- 仓库根说明写有 v0.2：可通过其已有 SSH 配置只读同步 LivingMemory 文档、记忆原子和来源关系；不加同步参数时使用演示数据。
- 展示模块自身 README 仍标 v0.1，说明只读快照、时间线、遗忘模拟及线索召回。两处文档尚不一致，v0.2 的详细验收文档本次未成功获取，因此不把仓库自述等同于本机验收。
- 可以确认的是：星图界面与实际记忆写入/遗忘策略有不同边界。界面中的遗忘曲线和节点距离，不能直接当成机器人真实遗忘程度或模型内部思维。
- 对本项目的判断：非常接近“识海/星海”展示需求，可优先研究其只读快照协议，制作现有记忆的适配器；暂不因此更换聊天框架。

### 4. Memobase

- 仓库：https://github.com/memodb-io/memobase
- 自托管说明：https://github.com/memodb-io/memobase/blob/main/src/server/readme.md
- 能力侧重用户画像和事件时间线，支持批量整理和独立 API；使用 FastAPI、Postgres、Redis，可配置模型及事件向量检索。
- 对本项目的判断：若主要诉求是记住用户兴趣、生活经历、关系变化，可作为独立记忆后端候选；它本身不等于星海式图谱界面。

## 推荐顺序

1. 保留现有记忆与聊天服务，先备份，并建立只读可视化适配器；默认逐会话展示，不把两个好友和群的记忆混合。
2. 优先补记忆条目编辑、固定、不再使用、来源查看和检索预览。人工确认的资料不应被普通聊天自动覆盖。
3. 用合成数据比较关键词检索与语义检索：同义表达召回、旧事实修正、不同成员隔离、重复记忆及每次输入预算。
4. 若现有检索仍不够，再试验 LivingMemory 适配或 Memobase 独立服务。试验通过前不替换生产记忆，不清空现有数据。

建议记录每轮实际注入字符数、记忆整理模型调用数、检索命中和错误归属；以这些结果判断是否变好，而不是只看节点数量或演示视频。

## 本次主动消息的配置含义

新功能使用原有账号核验、会话名单、发送队列、运行代次和总额度。主动消息另有跨重启保存的共享日账本：全天 0–24 时、至少空闲 60 分钟、每轮最多 5 条、所有选中会话合计每天最多 20 条。

达到空闲门槛后额外随机等待 0–60 分钟；部分评估直接保持安静，不调用模型。进入模型评估后也可返回空消息。每次评估后随机等待 60–120 分钟再考虑该会话；不同会话的模型评估至少间隔 15 分钟，全账号每天最多 40 次模型评估。上述限制是上限，不保证发言次数。

每条外发前重新检查会话活动和额度；有人接话会取消后续消息。发送结果未知仍计数并暂停，不自动重发。暂停或重启后不会立即补发旧的主动任务；重新运行后先重新满足空闲门槛。

当前“贴吧”性格由已保存的会话/默认配置决定，本次主动消息沿用它，不新增自定义人设。
