# 项目结构与部署复现

本文记录本仓库的代码组织、已验证环境及 Windows + WSL2 + QQ 的复现流程。日期：2026-10-29。

## 1. 项目结构

```text
deepseek-dafeiyu/
├── README.md                     仓库入口与本地改进说明
├── AGENTS.md                     仓库协作约定
├── docs/                         本仓库部署复现文档
├── dafeiyu-bot/                  应用源码，基于上游 dafeiyu-bot
│   ├── Package.swift             Swift 包及固定版本依赖
│   ├── Sources/BotCore/          会话策略、人设、记忆、主动消息策略与额度
│   ├── Sources/WeChatAIBot/      QQ 引擎、DeepSeek 客户端、OneBot、本机控制服务
│   ├── Resources/QQControl/      Web 面板 HTML / JavaScript / CSS
│   ├── Resources/QQStickers/     表情资源及来源声明
│   ├── Tests/BotCoreTests/       核心策略测试
│   ├── Tests/QQEngineTests/      本机模拟 QQ 与模型的集成测试
│   ├── scripts/                  构建、测试、配置初始化及公开文件检查
│   ├── deploy/                   原项目的容器创建、入口与升级脚本
│   └── docs/                     原项目完整使用说明
├── dafeiyu-deployment/           本次部署的 Windows 入口及 Linux 辅助脚本
└── dafeiyu-wsl/                  本机 WSL 虚拟磁盘，忽略，不上传
```

上游代码与新增改动按普通文件提交，不使用指向上游旧版本的 Git 子模块。本机原子仓库的 Git 元数据保存在忽略目录 `.local-git-backups/`；这份备份不会被推送。

## 2. 运行链路与数据位置

```text
手机 QQ → NapCat 容器 → OneBot WebSocket → Swift QQEngine → DeepSeek API
                                 ↑                 ↑
                         127.0.0.1:3001       本机 Web 控制面板
```

QQ 桥接与机器人在同一个专用 Ubuntu 中。NapCat 管理页使用 `http://127.0.0.1:6099/webui/`；大肥鱼面板地址由每次启动动态产生，包含本次访问凭证。

| 位置（Linux 用户主目录下） | 内容 | 随 Git 分发 |
|---|---|---|
| `~/dafeiyu-bot` | 应用源码链接和构建产物 | 源码分发；构建产物忽略 |
| `~/deployment` | 安装后的运行辅助脚本 | 脚本原件在仓库 |
| `~/qq-runtime/config` | NapCat / OneBot 令牌与账号配置 | 否，首次部署重新生成 |
| `~/.local/share/dafeiyu` | `qq-state.json` 等会话设置、额度与记忆 | 否 |
| `~/.local/state/dafeiyu-deployment` | 面板日志、PID、单实例锁 | 否 |
| Docker 卷 `qq-ai-data` | QQ 登录及客户端数据 | 否 |

API Key 由使用者自行创建并保存在自己的密码管理器中。当前 Linux 版只在运行内存中持有模型凭证，重启后重新填写同一个 Key，不需要每次创建新的。

## 4. 准备 Windows 与专用 Ubuntu

安装 Git for Windows。启用 WSL2、虚拟化与 systemd，参照 [微软 WSL 安装说明](https://learn.microsoft.com/windows/wsl/install)。在 PowerShell 克隆整个仓库：

```powershell
git clone https://github.com/Kriswagn/deepseek-dafeiyu.git E:\learn_project\dafeiyu
Set-Location E:\learn_project\dafeiyu
wsl --version
wsl --list --verbose
```

新机器可在支持这些选项的 WSL 版本中安装独立环境：

```powershell
wsl --install --distribution Ubuntu-24.04 --name Dafeiyu-Ubuntu --location E:\learn_project\dafeiyu\dafeiyu-wsl
```

首次进入按提示创建普通用户 `dafeiyu`，自行设置 Linux 密码。若 WSL 不支持 `--name` / `--location`，先按本机 `wsl --help` 和微软文档完成安装，再将下面启动器的 `-Distro` 调整为实际名称。已有同名环境时跳过安装，不能注销现有环境来“重新部署”。

不要在 WSL 使用中直接移动 `ext4.vhdx`。磁盘移动后可能出现注册路径与实际路径不一致；本仓库保留修复工具用于排障，普通安装不需要执行它。

## 5. 安装 Linux 依赖和源码

下面命令在专用 Ubuntu 的普通用户终端执行：

```bash
sudo apt-get update
sudo apt-get install -y git curl ca-certificates gnupg build-essential pkg-config clang \
  libicu-dev libcurl4-openssl-dev libxml2-dev libsqlite3-dev libssl-dev libncurses-dev \
  python3 python3-pil tzdata
```

按 [Swift 官方 Ubuntu 24.04 安装说明](https://www.swift.org/install/linux/ubuntu/24_04/) 安装 Linux Swift 6.1.3，并核验官方发行包签名。按 [Docker 官方 Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/) 安装专用环境的 Docker Engine。本次不依赖 Docker Desktop，也不需要把普通用户加入 docker 组。

```bash
swift --version
python3 -c 'from PIL import Image; print(Image.__version__)'
sudo systemctl start docker
sudo docker version
cd ~
git clone https://github.com/Kriswagn/deepseek-dafeiyu.git
bash ~/deepseek-dafeiyu/dafeiyu-deployment/install-runtime.sh
```

安装脚本把 `~/dafeiyu-bot` 链接到本次克隆的应用源码，安装 Linux 辅助脚本，并仅在没有配置时生成随机令牌。源码放在 WSL 的 Linux 文件系统内，避免直接在 Windows 挂载目录中编译；其磁盘仍可保存在 E 盘。

Windows 工作目录与 WSL 编译目录是两份文件；修改 Windows 文件不会自动替换运行中的 Linux 程序。新环境按本文从同一仓库克隆，后续在各自副本同步提交，再按备份、停止、构建和启动的顺序更新。此前已经部署的独立 WSL 源码副本不会因为这次 Windows 仓库初始化而自动切换远程或被覆盖。

## 6. 测试、构建及创建 QQ 容器

```bash
cd ~/dafeiyu-bot
bash scripts/test.sh
python3 scripts/check-public.py
bash scripts/build-linux.sh
python3 scripts/test-control-panel.py dist/dafeiyu-linux/dafeiyu
python3 scripts/test-onebot-transport.py dist/dafeiyu-linux/dafeiyu
sudo env DAFEIYU_RUNTIME_USER="$(id -un)" bash ~/deployment/provision-qq.sh
```

`provision-qq.sh` 用于本次验证的 amd64 镜像；其他架构可参考应用内 `deploy/qq-container-create.sh`。容器仅绑定本机的 6099 和 3001，保留 QQ 数据卷，限制 2 GB 内存、2 CPU、512 PID；默认不自动重启。

首次下载依赖与镜像需要网络。若需要代理，单独配置本机环境及专用 Ubuntu 的 Docker，并确保它们可以访问代理；不要复制他人机器的 WSL 网关地址。普通启动复用现有镜像和构建产物。

## 7. 登录及本次配置

在 Windows 仓库中双击 `dafeiyu-deployment/Start.cmd`，保持启动进程运行。默认发行版和用户名称与前述步骤一致；使用其他名称时，通过 PowerShell 调用 `Dafeiyu.ps1 -Action start -Distro <名称> -RuntimeUser <用户>`。

1. 打开 NapCat 管理页，运行 `Copy-WebUI-Token.cmd`，粘贴后登录；使用机器人 QQ 扫码。
2. 核对当前 QQ 账号的 OneBot 正向 WebSocket：端口 3001、Array 消息、自身消息上报和心跳开启。Access Token 要与生成的配置一致。账号专用配置应以实际登录后的网络页为准。
3. 在大肥鱼面板保存 OneBot 地址 `ws://127.0.0.1:3001` 及自己的机器人 QQ 号。
4. 运行 `Copy-OneBot-Token.cmd`，将其填入大肥鱼面板；再填写自己的 DeepSeek API Key，点击“连接并核对账号”。两种 Token 用途不同。
5. 从实际联系人列表添加并启用允许回复的好友和群，保存设置。普通好友添加、入群与群管理员批准需通过 QQ 正常完成。
6. 使用系统内置“贴吧”性格。当前源码支持会话单独选性格，会话设置优先于默认性格。
7. 先单次验收普通私聊、群内真正 @ 的回复，再按需开启持续回复。
8. 如需复现本次主动消息：在“范围与回复 → 空闲时主动发消息”勾选自己的目标，设置全天 0–24 时、最少空闲 60 分钟、每轮最多 5 条、每天合计最多 20 条，保存后开始运行。

空闲门槛只是候选条件，之后还有随机等待和是否值得发言的判断；可能保持安静，不保证每小时发送。所有选中会话共享主动消息日额度。连续发言期间有人接话，会取消剩余消息。原有总发送和模型调用额度仍然生效。新的第三方记忆后端尚未接入。

## 8. 验证、停止、备份与升级

```bash
sudo docker ps --filter name=qq-ai
sudo python3 ~/deployment/check-login.py
```

登录检查正常时应显示 `isLogin=true`、`loginPhase=ready`。面板应显示 QQ 已连接、预期账号一致，开始后显示运行中。此次改动的完整自动测试为 183 项，发布构建和打包控制面板检查均已通过；自动测试只使用合成身份，不给真实会话发测试消息。

通过 Windows 的 `Stop.cmd` 停止机器人和 QQ 容器。只想暂停回复时使用面板“暂停”，无需退出 QQ。停止后再替换运行二进制；不要覆盖正在执行的文件。

升级前备份用户数据目录、QQ 配置及 Docker 数据卷，并保留旧运行包。当前运行数据不会随着代码推送上传；仅克隆 Git 仓库可以重建软件环境，恢复原有登录和记忆还需要使用者自己的私有备份。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| NapCat 页面 `token is invalid` | 使用 WebUI Token；OneBot Token 填在大肥鱼连接面板 |
| 程序重启后要求 Key | 从自己的密码管理器取同一个 Key；平台通常不再显示旧密钥全文 |
| 面板能打开但无法连接 QQ | 核对 QQ 登录、当前账号的 WS 配置和 3001，不仅检查端口 |
| 主动消息没有按小时发送 | 这是预期行为；检查运行状态、目标、最近活动、额度和运行记录 |
| 磁盘路径不存在 | 核对真实 VHDX 位置与 WSL 注册信息，先备份再修复 |
| GitHub 下载慢 | 核对当前网络和命令级代理，保留固定镜像摘要及校验 |
